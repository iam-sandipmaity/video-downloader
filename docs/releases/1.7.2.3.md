# Video Downloader 1.7.2.3

`1.7.2.3` is a quality-of-life and compatibility release focused on easier library management, clearer recovery guidance, safer playback defaults, and smoother runtime behavior.

## Highlights

- Added inline search to both Downloads and History so people can filter by title, source, file name, saved path, and related task diagnostics
- Upgraded queue recovery guidance so failed items can point more clearly to likely causes such as login or region restrictions, temporary network trouble, FFmpeg post-processing failures, runtime issues, or extractor mismatches
- Added an easier external-player fallback path and broader media-container recognition across in-app playback and open-with flows
- Added a `repoSafe` build flavor that keeps yt-dlp auto-update off by default for repository-friendly distribution builds

## Improved

- Downloads and History now feel more practical once the app has accumulated a larger media library or a longer task history
- Recovery messaging is more actionable and better aligned with the app's existing cookies, YouTube access, and retry flows
- The Downloads header is more compact, and automatic video choices now lean toward more device-friendly defaults when no exact format is picked manually
- Variable-support formats such as `WEBM` and `MKV` now show only a short playback heads-up instead of a persistent warning

## Fixed

- Failed queue items no longer rely on one generic help block for very different error conditions
- Recovery suggestions now better match the actual failure pattern shown in task output and recent diagnostics
- `WAV` and `FLAC` extraction no longer receive invalid bitrate arguments, and post-processing failures now recover already-downloaded source audio more reliably
- FFmpeg setup now prefers the newer linked or overlay runtime before falling back to the legacy bundled binary
- More audio and video containers now receive correct MIME hints and playback routing instead of being handled inconsistently

## Notes

Built-in playback still depends on device codec support for some advanced containers and codecs, but this release improves default choices, format handling, and fallback options so fewer files feel ambiguous in the app.
