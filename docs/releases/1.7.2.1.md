# Video Downloader 1.7.2.1

`1.7.2.1` is a compatibility and runtime follow-up release focused on restoring broader site support after the `1.7.2.0` security hardening pass.

## Highlights

- Restored safer non-YouTube analysis retries for slower sites without bringing back insecure TLS downgrade behavior
- Switched yt-dlp runtime updates back onto yt-dlp's own self-update path for better extractor compatibility recovery
- Improved resilience for generic-site and article-video flows that had started failing or surfacing fewer formats after `1.7.2.0`
- Refreshed the repository README and new wiki content set with clearer documentation, a categorized screenshot gallery, and more consistent GitHub-friendly preview layout
- Tightened Android chooser visibility so the app appears for link sharing and audio or video file opening, instead of unrelated browser or generic file targets
- Changed CI so normal builds still upload APK artifacts, but nightly GitHub prereleases are only published when a maintainer explicitly asks for one

## Fixed

- Added extended-timeout analysis retries for transient non-YouTube link-analysis failures while keeping certificate validation strict
- Reworked yt-dlp update installation so the embedded runtime advances through yt-dlp's supported updater flow instead of raw file replacement
- Removed invalid `--merge-output-format` handling from audio-extraction downloads, so audio-only flows no longer fail on sites that expose standalone `m4a` formats
- Reclassified audio-only source formats more accurately, so audio sites such as JioSaavn now surface their analyzed `m4a` choices under `Audio only` and keep unavailable video tabs disabled
- Improved postprocessing recovery and format-container routing already queued for the `1.7.2.1` line, including cleaner VP9/WebM merge handling and stronger salvage of completed media
- Restored sanitized per-task debug traces and cleaned up stray thumbnail sidecars left behind by optional postprocessing failures
- Stopped the app from advertising itself too broadly in Android choosers for unrelated `open with` and browser-style targets

## Notes

This release keeps the security posture introduced in `1.7.2.0`, but focuses on recovering practical compatibility where the stricter runtime behavior had become too brittle on real sites while also tightening release workflow control and documentation quality.
